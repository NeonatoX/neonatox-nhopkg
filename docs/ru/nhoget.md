# nhoget — инструмент унифицированной загрузки

`nhoget` — это унифицированная система загрузки для менеджера пакетов nhopkg. Она предоставляет прозрачные возможности загрузки HTTP/HTTPS и VCS всем компонентам nhopkg — сборкам, установкам, обновлениям репозиториев и созданию исходных пакетов — а также служит автономным CLI-инструментом, который можно использовать из скриптов пост-установки, рецептов сборки или терминала.

## Обоснование

До появления `nhoget` nhopkg использовал разрозненные вызовы `wget` и `git clone`, разбросанные по всему коду. Это затрудняло:

- Смену бэкендов загрузки (GNU wget, curl, BusyBox wget)
- Добавление типов VCS, помимо git (svn, hg)
- Применение согласованных политик повторов, тайм-аута и возобновления
- Аудит и расширение поведения загрузки

`nhoget` централизует всю логику загрузки в одной библиотеке (`libnhopkg_download`), доступ к которой предоставляется через CLI-инструмент, и которая прозрачно подключается nhopkg.

## Гарантия прозрачности

`nhoget` — это **прозрачная замена**: ни один существующий рабочий процесс nhopkg, формат nhoid или пользовательский интерфейс не изменились. Те же опции (`nhopkg -b`, `-C`, `-S`, `-U`) ведут себя одинаково. Внутри каждый `wget` и необработанный `git clone` заменён на `nhoget_url` / `nhoget_vcs`.

## Команды

### `download`

Загружает файл через HTTP/HTTPS.

```
nhoget download [опции] <url> [<dest>]
```

Если `<dest>` опущен, имя файла выводится из URL. Используйте `-o`, чтобы указать точный путь вывода, или `-O`, чтобы указать каталог вывода. Поддерживается проверка хэша с помощью `--hash`.

### `clone`

Клонирует VCS-репозиторий.

```
nhoget clone [опции] <url> [<dest>]
```

По умолчанию используется git. Для других типов VCS используйте `--type svn` или `--type hg`. Назначение по умолчанию — базовое имя URL (с удалённым `.git` для URL git).

### `fetch`

Автоматически определяет тип источника по URL и загружает или клонирует.

```
nhoget fetch [опции] <url> [<dest>]
```

Правила определения:

| Шаблон URL | Поведение |
|-------------|-----------|
| `git+<url>` или `*.git` | Клонирование Git |
| `svn+<url>` | Извлечение Subversion (checkout) |
| `hg+<url>` | Клонирование Mercurial |
| Обычный URL | Загрузка tarball + автоматическая распаковка |

Tarball извлекаются с `--strip-components=1` в каталог назначения. Поддерживаемые форматы: `.tar.zst`, `.tar.xz`, `.tar.bz2`, `.tar.gz`, `.zip`, `.AppImage`.

Для типов VCS `nhoget fetch` пытается выполнить инкрементальное обновление (fetch + checkout), если каталог назначения уже существует, возвращаясь к новому клонированию при неудаче.

### `patch`

Загружает файл патча или diff, сохраняя его с исходным именем файла из URL.

```
nhoget patch <url>
```

Файл сохраняется как `../<имя-файла>` (родитель рабочего каталога).

## Опции

| Короткая | Длинная | Описание |
|-------|------|-------------|
| `-o` | `--output FILE` | Сохранить в конкретный файл (только загрузка) |
| `-O` | `--output-dir DIR` | Сохранить в каталог |
| `-r` | `--resume` | Возобновить частичную загрузку |
| `-t` | `--timeout SECS` | Тайм-аут соединения (по умолчанию: 20) |
| | `--retries N` | Количество повторов (по умолчанию: 3) |
| `-q` | `--quiet` | Подавить необязательный вывод |
| `-v` | `--verbose` | Подробный вывод |
| | `--hash TYPE:VALUE` | Проверить хэш после загрузки (например, `sha256:abc...`) |
| | `--type TYPE` | Принудительно задать тип источника: `tarball`, `git`, `svn`, `hg` |
| | `--ref REF` | Ссылка VCS (тег, ветка, коммит для git; ревизия для svn) |
| | `--depth N` | Глубина неполного клонирования (только git) |
| | `--backend BACKEND` | Принудительно задать бэкенд: `wget`, `curl`, `wget-bb`, `auto` |
| `-h` | `--help` | Показать справку |
| | `--version` | Показать версию |

## Бэкенды

Бэкенд `auto` проверяет в следующем порядке:

1. **GNU wget** — предпочтителен для обратной совместимости (не curl, несмотря на то, что curl более переносим)
2. **curl** — используется, если GNU wget недоступен
3. **BusyBox wget** — работает с HTTPS; повторы реализованы через ручной цикл (в BusyBox отсутствует флаг `-t`)

## Библиотека `libnhopkg_download`

Вся логика загрузки находится в библиотеке **`libnhopkg_download`** (устанавливается
как `/usr/lib/nhopkg/libnhopkg_download`). CLI `nhoget` — это тонкая обёртка над
ней, и библиотека также подключается напрямую через `source` nhopkg, `nhopkg-src` и
разрешателем зависимостей. Основные функции:

Функция | Назначение
---|---
`nhoget_detect_backend()` | Выбирает бэкенд загрузки (`wget`, `curl`, `wget-bb`), учитывая `NHOGET_BACKEND`.
`nhoget_url()` | Загружает один URL с повторами, тайм-аутом и опциональным возобновлением.
`nhoget_url_wget_bb()` | Вариант для BusyBox wget (ручной цикл повторов; в BusyBox нет `-t`).
`nhoget_verify_hash()` | Проверяет загруженный файл по спецификации хэша `TYPE:VALUE`.
`nhoget_vcs()` / `nhoget_vcs_git()` / `nhoget_vcs_svn()` / `nhoget_vcs_hg()` | Операции клонирования/извлечения VCS.
`nhoget_fetch()` | Автоматически определяет тип источника и направляет его по пути URL или VCS.
`nhoget_fetch_tarball()` | Загружает и автоматически распаковывает tarball (с `--strip-components=1`).

Поведение возобновления и проверки хэша, таким образом, идентично независимо от
того, запускается ли загрузка из CLI `nhoget`, из рецепта сборки или из вызовов
`nhoget_url` разрешателя зависимостей.

## Конфигурация

Поведение управляется переменными окружения или `/etc/nhopkg/nhopkg.conf`:

| Переменная | По умолчанию | Описание |
|----------|-------------|-------------|
| `NHOGET_BACKEND` | `auto` | Выбор бэкенда (`wget`, `curl`, `wget-bb`, `auto`) |
| `NHOGET_TIMEOUT` | `20` | Тайм-аут соединения в секундах |
| `NHOGET_RETRIES` | `3` | Количество повторов загрузки |
| `NHOGET_RESUME` | `yes` | Включить возобновление частичных загрузок |

## Префиксы URL

VCS-репозитории могут быть указаны с префиксами URL:

- `git+https://example.com/repo` — Git-репозиторий
- `svn+https://example.com/svn/repo` — Subversion-репозиторий
- `hg+https://example.com/repo` — Mercurial-репозиторий
- `https://example.com/pkg.tar.zst` — Обычный tarball (автоматическая распаковка)

Для обратной совместимости URL, оканчивающиеся на `.git`, также рассматриваются как Git-репозитории (префикс `git+` не требуется).
