# 5\. Безопасность и GPG-подписи

**nhopkg** включает встроенную поддержку проверки GPG-подписей, что гарантирует подлинность и целостность пакетов перед установкой.

## Библиотека `libnhopkg_crypto`

Все криптографические операции реализованы в библиотеке
**`libnhopkg_crypto`** (устанавливается как `/usr/lib/nhopkg/libnhopkg_crypto`) и
подключаются как `nhopkg`, так и `nhopkg-repos`. Модуль активен только тогда, когда
доступен бинарный файл `gpg` (`CRYPTO_GPG_AVAILABLE`).

### Подпись и проверка пакетов

Функция | Назначение
---|---
`crypto_sign_package()` | Подписывает `data.tar.zst` во временном каталоге сборки с помощью `NHOPKG_SIGN_KEY`, используя `--detach-sign --armor`, создавая `signature.gpg`. Пропускается, когда `NHOPKG_SIGN_PACKAGES` не равно `yes`.
`crypto_sign_package_ext()` | То же, но для внешнего `data.tar.zst` (используется `nhopkg-repos`).
`crypto_verify_signature()` | Проверяет подписи пакетов относительно доверенной связки ключей. Поддерживает **мультиподпись**: находит все `signature*.gpg` во временном каталоге и завершается успешно, если проверку проходит хотя бы одна. Учитывает `NHOPKG_REQUIRE_SIGNATURE` (прерывает работу, когда требуется подписанный пакет).
`crypto_sign_file()` | Низкоуровневая откреплённая подпись (`--detach-sign --armor`) любого файла.
`crypto_verify_file()` | Низкоуровневая проверка откреплённой подписи относительно доверенной связки ключей.

### Подпись метаданных репозитория

`nhopkg-repos` также подписывает метаданные репозитория, а `nhopkg -U` проверяет их,
прежде чем принять обновление:

Функция | Назначение
---|---
`crypto_sign_repo_metadata()` | Создаёт `<файл>.asc` для каждого файла метаданных `*.zst`, а также `lastsync.asc` в каталоге репозитория.
`crypto_verify_repo_metadata()` | Проверяет каждую пару `*.zst`/`.asc` и `lastsync.asc`; учитывает `NHOPKG_REQUIRE_SIGNED_METADATA`.

### Управление ключами

Функция | Назначение
---|---
`crypto_init_keyring()` | Автоматически инициализирует доверенную связку ключей: если `pubring.kbx` отсутствует, но существует `nhopkg-repo.pub`, импортирует его автоматически.
`crypto_generate_key()` | Генерирует новую пару ключей GPG для сопровождающего (поддерживает batch/файл парольной фразы для CI/CD).
`crypto_import_key()` / `crypto_export_key()` / `crypto_list_keys()` / `crypto_remove_key()` | Управляют ключами в доверенной связке ключей.
`crypto_verify_incoming()` | Проверяет подписи входящих пакетов при добавлении их в репозиторий (процесс работы соавторов).

## Общие сведения

Бинарные пакеты (`.nho`) могут содержать необязательный файл `signature.gpg`, который
является откреплённой GPG-подписью файла `data.tar.zst`.

Доверенные ключи хранятся в:
    
    
    /etc/nhopkg/trusted-keys/

## Конфигурация безопасности

Переменная| По умолчанию| Описание  
---|---|---  
`NHOPKG_VERIFY_SIGNATURE`| yes| Включить проверку GPG  
`NHOPKG_REQUIRE_SIGNATURE`| no| Требовать подписанные пакеты  
`NHOPKG_TRUSTED_KEYS_DIR`| /etc/nhopkg/trusted-keys/| Каталог доверенной связки ключей  
`NHOPKG_SIGN_PACKAGES`| yes| Подписывать пакеты при сборке  
`NHOPKG_SIGN_KEY`| repo@neonatox.vegnux.com| Ключ подписи по умолчанию  
`NHOPKG_VERIFY_INCOMING`| no| Проверять подписи входящих пакетов (соавторы)  
`NHOPKG_SIGN_REPO_METADATA`| yes| Подписывать файлы метаданных репозитория  
`NHOPKG_VERIFY_REPO_METADATA`| yes| Проверять метаданные репозитория при `nhopkg -U`  
`NHOPKG_REQUIRE_SIGNED_METADATA`| no| Требовать действительные подписи метаданных  
  
**Автоматическая инициализация связки ключей:** если `pubring.kbx` не существует,
но присутствует `nhopkg-repo.pub`, nhopkg импортирует его автоматически. 

## Порядок проверки

  1. Пользователь устанавливает пакет.
  2. Если проверка включена, nhopkg проверяет `signature.gpg`.
  3. Если подпись отсутствует, а она требуется → прерывание.
  4. Если подпись недействительна → прерывание.
  5. Если подпись действительна → продолжение.

Пакеты с мультиподписью принимаются, когда **хотя бы одна** `signature*.gpg`
проходит проверку относительно доверенной связки ключей.

## Рекомендации

  * Держите проверку подписей включённой в производстве.
  * Включайте обязательные подписи для критически важных систем.
  * Защищайте ваш закрытый ключ подписи.
