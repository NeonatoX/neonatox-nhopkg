# Основные команды — nhopkg v0.5.1

nhopkg — универсальный менеджер бинарных и исходных пакетов. На этой странице документированы все команды и опции, принимаемые бинарным файлом `nhopkg`. Административные задачи (сборка пакетов, управление репозиториями, создание пользователей) выполняются вспомогательными инструментами, упомянутыми в конце.

## Справочник команд

| Короткая | Длинная | Описание |
|-------|------|-------------|
| `-i` | `--install` | Установить локальный бинарный пакет `.nho` |
| `-S` | `--super-install` | Установить пакет из удалённого репозитория |
| `-d` | `--dios` | То же, что и `-S` / `--super-install` |
| `-b` | `--build` | Собрать и установить исходный пакет `.srcnho` |
| `-C` | `--super-build` | Клонировать Git-репозиторий и собрать/установить из его рецепта `nhoid` |
| `-r` | `--remove` | Удалить установленный пакет |
| | `--purge` | Удалить пакет вместе со всеми его обратными зависимостями |
| `-B` | `--backup` | Воссоздать бинарный пакет `.nho` из уже установленного пакета |
| `-l` | `--list` | Перечислить все пакеты, установленные nhopkg |
| `-n` | `--info` | Показать подробную информацию о пакете (установленный, в репозитории или локальный `.nho`) |
| `-w` | `--show` | Перечислить все файлы, принадлежащие установленному пакету |
| `-s` | `--search` | Искать пакеты в метаданных локального репозитория |
| `-t` | `--list-repo` | Перечислить все пакеты, доступные в настроенных репозиториях |
| `-k` | `--check` | Проверить целостность установленного пакета (проверить, что каждый перечисленный файл существует) |
| `-y` | `--upgrade` | Обновить все установленные пакеты до последней версии, доступной в репозиториях |
| `-U` | `--update` | Синхронизировать все настроенные базы данных репозиториев (`core.packages.tar.zst`, `core.files.tar.zst`, `lastsync`) |
| `-u` | `--update-db` | Пересобрать локальную базу данных расположения файлов (`updatedb` / `plocate`) |
| `-x` | `--update-shooters` | Обновить системные кэши: схемы GLib, кэш значков, базу данных desktop, базу данных MIME, man-страницы, кэш шрифтов, кэш разделяемых библиотек и загрузчики GDK pixbuf |
| `-e` | `--clean` | Удалить кэшированные пакеты `.nho` из кэша загрузок; с `-R` также очищает каталог сборки |
| `-X` | `--strip-binaries` | Удалить отладочные символы из ELF-бинарных файлов и разделяемых объектов при `--build` (экспериментально) |

## Опции (флаги)

| Длинная | Описание |
|------|-------------|
| `-v`, `--verbose` | Включить подробный вывод |
| `-p`, `--preserve-files` | Принудительно сохранять файлы пакета при его удалении |
| `-R`, `--recursive` | Отвечать «да» на все запросы (неинтерактивный режим) |
| `-o`, `--output DIR` | Записывать вывод команды (list, info, show) в файл журнала в каталоге DIR |
| `--root DIR` | Работать с альтернативным корневым каталогом (для bootstrap, chroot или контейнеров); состояние, репозитории и зависимости разрешаются внутри целевой системы, а пост-установочные хуки / обновления кэша выполняются там через chroot |
| `--no-check-deps` | Пропустить разрешение зависимостей |
| `--force-check-deps` | Принудительно выполнить разрешение зависимостей, даже если оно отключено в конфигурации |
| `--no-check-arch` | Пропустить проверку архитектуры |
| `--force-check-arch` | Принудительно выполнить проверку архитектуры, даже если она отключена в конфигурации |
| `--no-check-sha256` | Пропустить проверку контрольной суммы SHA-256 |
| `--force-check-sha256` | Принудительно выполнить проверку контрольной суммы, даже если она отключена в конфигурации |
| `--sign-package` | Подписать бинарный пакет с помощью GPG при `--build` |
| `--no-sign-package` | Пропустить GPG-подпись |
| `--verify-package-signature` | Проверить GPG-подпись пакета перед его установкой |
| `--no-verify-package-signature` | Пропустить проверку подписи |
| `--license` | Показать краткое уведомление о лицензии |
| `--license-all` | Показать полный текст лицензии GPL |
| `--version` | Показать версию nhopkg и авторские права |
| `--help` | Показать встроенную справочную страницу |
| `--` | Остановить разбор аргументов (всё после него считается именем пакета) |

> **Примечание:** Опции `--no-check-sums` и `--force-check-sums` являются псевдонимами для `--no-check-sha256` и `--force-check-sha256` соответственно.

## Примеры

```bash
# Установить локальный пакет .nho
sudo nhopkg -i gimp-3.0.4-n20260523.linux-x86_64.nho

# Установить из репозитория (с разрешением зависимостей)
sudo nhopkg -S gimp

# То же, что и выше
sudo nhopkg --super-install gimp
sudo nhopkg -d gimp

# Собрать из исходного рецепта
sudo nhopkg -b foo.srcnho

# Собрать напрямую из Git-репозитория
sudo nhopkg -C foo

# Удалить пакет
sudo nhopkg -r gimp

# Удалить пакет и всё, что от него зависит
sudo nhopkg --purge gimp

# Обновить метаданные репозиториев
sudo nhopkg -U

# Обновить все установленные пакеты
sudo nhopkg -y

# Перечислить установленные пакеты
nhopkg -l

# Показать подробную информацию (поиск в репозиториях, установленных или локальном .nho)
nhopkg -n gimp

# Показать файлы, принадлежащие пакету
nhopkg -w gimp

# Найти пакеты по шаблону
nhopkg -s gimp

# Проверить целостность установленного пакета
sudo nhopkg -k gimp

# Очистить кэш загрузок
sudo nhopkg -e

# Очистить кэш и каталог сборки
sudo nhopkg -e -R

# Установить с альтернативным корнем (например, для chroot)
sudo nhopkg -i foo.nho --root /mnt/chroot

# Включить подробный вывод
nhopkg -v -n gimp

# Записать вывод списка в файл
nhopkg -l -o /tmp

# Удалить отладочные символы при сборке
sudo nhopkg -X -b foo.srcnho

# Удалить пакет, сохранив его файлы
sudo nhopkg -r gimp -p
```

## Корневой режим (`--root`)

`--root DIR` устанавливает, обновляет или удаляет пакеты в **альтернативном корневом каталоге** вместо живой системы. Полезно для начальной загрузки новой системы, chroot или контейнеров. Целевой каталог уже должен существовать.

- Состояние пакетов (`/var/nhopkg/packages`, `files`, `repo`, `cache`) находится **внутри целевой системы** (`DIR/var/nhopkg`).
- Синхронизация репозиториев (`--update`), разрешение зависимостей и проверки конфликтов работают с целевым корнем, а не с хостом.
- Файлы извлекаются внутрь `DIR`.
- Хуки `npostinstall()` и обновления кэша (`shooter_updates`: схемы GLib, кэши значков/MIME/рабочего стола, шрифты, `ldconfig`) **не** выполняются на хосте: они выполняются **внутри целевой системы** через chroot в частном пространстве имён монтирования с bind-mount `/dev`, `/proc`, `/sys` и `/run` с хоста. Для этого требуется `/bin/sh` внутри целевой системы.
- Если nhopkg ещё не установлен внутри целевой системы, обновления кэша пропускаются с предупреждением; после этого выполните `nhopkg -x` внутри целевой системы.
- Файлы `# Backup:` читаются и восстанавливаются внутри целевого корня.
- Неинтерактивно: запросы пропускаются при установке из репозитория.

```bash
# Установка в целевой каталог chroot
sudo nhopkg -i foo.nho --root /mnt/chroot

# Установка из репозитория внутрь целевой системы (с разрешением зависимостей)
sudo nhopkg -S foo --root /mnt/chroot

# Обновление всего внутри целевой системы
sudo nhopkg -y --root /mnt/chroot
```

> **Примечание:** `--root` — это не полная обёртка над `chroot`. Команда должна выполняться от root, и целевая система уже должна содержать основные пакеты (например, glibc, bash, nhopkg), прежде чем внутри неё можно будет выполнять хуки.
